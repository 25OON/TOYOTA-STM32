04 ตัวงูเก็บข้อมูลยังไง

เก็บสองชุดคู่กัน เพื่อให้เช็กชนตัวเองเป็น O(1)

static SnakeCell_t s_body[512];      /* ring buffer   1024 ไบต์ */
static uint8_t     s_occupancy[512]; /* 0 ว่าง 1 งู 2 อาหาร  512 ไบต์ */
static uint16_t    s_headIndex;
static uint16_t    s_length;

ring buffer บอก ลำดับ ว่าหางไหนจะหายก่อน ส่วน occupancy บอก ช่องนั้นมีอะไร ทำให้ตรวจชนตัวเองได้ในขั้นตอนเดียว แทนที่จะไล่ดูทั้งตัวงูที่ยาวได้ถึง 512 ช่อง เปลืองแรม 512 ไบต์แลกความเร็ว

หนึ่งก้าวของงู

1. รับทิศที่ขอ → ถ้าเป็นทิศตรงข้ามกับที่วิ่งอยู่ ให้เมิน
2. คำนวณช่องถัดไปจากหัว
3. ออกนอกกรอบ?           → ตาย
4. occupancy == ตัวงู?    → ตาย   ⚠ ยกเว้นช่องหางที่กำลังจะหายรอบนี้
5. occupancy == อาหาร?    → length++, วางอาหารใหม่, ไฟฟ้าแวบ
   ไม่ใช่                 → ลบหาง
6. เขียนหัวใหม่ลง ring buffer + occupancy
ข้อ 4 คือกับดักคลาสสิกของเกมงู — ช่องหางต้องถือว่าว่าง เพราะหางจะเลื่อนออกในก้าวเดียวกัน ถ้าลืมข้อยกเว้นนี้ งูจะตายทั้งที่ไม่ควรตาย ตอนเดินตามหางตัวเอง
การวางอาหารใช้วิธี นับช่องว่างก่อน แล้วสุ่มว่าเอาช่องว่างลำดับที่เท่าไหร่ แล้วไล่หา = O(512) ต่อการกิน 1 ครั้ง · ห้ามสุ่มพิกัดซ้ำไปเรื่อย ๆ จนกว่าจะเจอช่องว่าง เพราะตอนงูยาวจะสุ่มไม่จบ

เฟรมหนึ่ง = 895 ไบต์ (ESC[?25l + ESC[H + 24 บรรทัด บรรทัดละ 35 ตัวอักษร) ส่ง 78 ms ที่ 115200 — สั้นกว่าก้าวที่เร็วที่สุด 100 ms

หกเทคนิคที่ทำให้ภาพไม่กะพริบ

  • ใช้ ESC[H เลื่อนเคอร์เซอร์กลับมุมบนซ้ายแล้ววาดทับ — ไม่ใช้ ESC[2J ล้างจอทุกเฟรม
  • ทุกบรรทัดเติมช่องว่างให้เต็ม 35 ตัวอักษรเสมอ ของเดิมบนจอจึงถูกทับหมด
  • บรรทัดสุดท้ายไม่ใส่ CR LF ไม่งั้นเคอร์เซอร์ตกไปบรรทัดที่ 25 แล้วดันจอเลื่อน
  • ส่ง ESC[?25l ซ้ำทุกเฟรม เผื่อเปิด terminal หลังบอร์ดบูตไปแล้ว
  • ถ้า UART ยังส่งเฟรมก่อนไม่จบ ให้ข้ามเฟรมนั้น ไม่รอ — รอบหน้าของ main loop ลองใหม่เอง
  • วาดซ้ำทุก 250 ms แม้งูไม่ขยับ เพื่อให้ SPEED และข้อความสถานะอัปเดตตอน IDLE/PAUSED

แรมที่ใช้: body 1024 + occupancy 512 + frame 895 + buffer UART 1024 + ของเดิม ≈ 5.5 KB จาก 128 KB

ทดสอบตรรกะด้วยแบบจำลองบนพีซีด้วย

เครื่องที่ใช้พัฒนาไม่มีคอมไพเลอร์ฝั่ง PC จึงลอก app_snake.c เป็น Python บรรทัดต่อบรรทัดแล้วทดสอบ

  • กับดักช่องหาง — หัวเข้าช่องที่หางกำลังจะหาย ต้องไม่ตาย
  • ชนกำแพงทุกด้าน · ชนลำตัวช่วงกลางจริง ๆ ต้องตาย
  • สั่งกลับหลัง 180° ต้องถูกเมิน
  • วางอาหารได้แม้เหลือช่องว่างช่องเดียว · กระดานเต็ม = WIN
  • เล่นอัตโนมัติแบบ BFS 30 เกม กิน 2,009 ครั้ง งูยาวถึง 95 ช่อง ตรวจ invariant ทุกก้าว

invariant ที่ตรวจ: ลำตัวไม่ทับกันเอง · จำนวนช่อง BODY เท่ากับ length พอดี · ทุกช่องของลำตัวถูกทำเครื่องหมายไว้จริง · อาหารไม่เกิน 1 เม็ด · ลำตัวต่อเนื่องกันทีละช่องไม่ขาดช่วง — ผ่านทั้งหมด

สาเหตุ: PB0 รับแกนตั้ง PC0 รับแกนนอน สลับกับที่ตั้งชื่อไว้ และขั้วแกนนอนกลับด้วย โค้ดจึงเห็นการดันขึ้นเป็น "แกนนอน" แล้วตัดสินเป็น LEFT ซึ่งโดนกฎห้ามกลับหลัง 180° เมินทิ้ง → งูไม่เลี้ยว

แก้: ค่าตั้งสามตัว ไม่ต้องถอดสาย — INPUT_SWAP_AXES 1U · INPUT_INVERT_X 1U · INPUT_INVERT_Y 0U

บทเรียน: อย่าเชื่อชื่อขาที่ตั้งเอง ให้วัดจริง และควรมีบรรทัดโชว์ค่า ADC ดิบบนจอไว้ตั้งแต่แรก

ไม่ใช่บั๊กโค้ดจอไหลลงไม่หยุด

เกิดตอนใช้ serialterminal.com แทน PuTTY — หน้าเว็บนั้นไม่ตีความรหัส ANSI จึงพิมพ์ ESC[H ออกมาเป็นตัวอักษร (เห็นเป็น ▯[H SCORE 0000) ทุกเฟรมเลยถูกต่อท้ายลงไปเรื่อย ๆ

ต้องใช้ terminal ที่รองรับ ANSI เท่านั้น — PuTTY, Tera Term หรือ Windows Terminal

จอเลื่อนขึ้น 1 บรรทัดทุกเฟรม

เฟรมสูง 24 บรรทัดเท่าหน้าต่าง PuTTY พอดี การใส่ CR LF ปิดท้ายบรรทัดสุดท้ายทำให้เคอร์เซอร์ ตกไปบรรทัดที่ 25 จอเลยถูกดันเลื่อน — แก้โดยไม่ใส่ CR LF ให้บรรทัดสุดท้าย

เคอร์เซอร์ค้างเป็นก้อนทึบท้ายจอ

ESC[?25l ส่งครั้งเดียวตอนบูต ถ้าเปิด PuTTY ทีหลัง session นั้นไม่เคยได้รับ — แก้โดยส่งนำหน้าทุกเฟรม เปลืองเพิ่ม 6 ไบต์

ช่องไฟบรรทัดดีบักเพี้ยน

ADC X=1985Y= 1995 เลขคอลัมน์พลาดไป 1 ช่อง · แก้แล้วและเปลี่ยนป้ายเป็นชื่อขาจริง PB0= PC0= POT= เพื่อไม่ให้สับสนระหว่างชื่อขากับแกนของก้านอีก
